# 代码学习指南

## 1. 先理解两种推荐和一个循环

项目的主循环是：

```text
设置变量与目标 → 生成/收集实验 → 数据检查 → 训练与验证
       ↑                                         ↓
  合并新结果 ← 做下一批实验 ← 推荐新的输入变量
```

推荐步骤可以使用两种策略：

- 指定目标反向推荐：用户描述希望目标变量达到的值、范围或阈值，程序搜索匹配度最高的输入。
- Pareto 多目标优化：不预先规定唯一目标组合，程序寻找不能在所有目标上被其他方案同时超越的输入。

主动学习是外层循环；两种推荐方法是循环中“下一步测哪里”的不同决策器。

## 2. 推荐阅读顺序

### `settings/project.yaml`

先从这里认识项目有哪些输入变量和目标变量。代码不再知道 A、B、C 或 X、Y、Z 的固定含义；它只读取设置。

输入只支持两种类型：

- `continuous`：任意连续数值。
- `integer`：必须是整数。

每个变量或约束都有自己的 `enabled` 开关。总约束开关位于 `constraints.enabled`。

### `config.py`

这一层把 YAML 转成不可变的数据对象，并尽早报告设置错误。重点函数：

- `load_project_config()`：加载并验证设置。
- `resolve_search_bounds()`：显式边界开启时直接使用上下界；关闭时从训练数据计算实际范围和扩展量。
- `feasible()`：同时检查边界、整数性和线性约束。
- `resolve_reference_point()`：把最大化/最小化目标统一到 BoTorch 的最大化空间。

### `data.py`

这一层负责数据进入模型前后的形状和质量：

- `candidate_pool()`：用 Sobol 序列生成候选，再处理整数变量并过滤约束。
- `initial_points()`：生成第一批实验。
- `frame()`：把 Tensor 转成带动态列名的表格。
- `load_data()`：检查列、空值、重复编号、数据来源、边界和约束。
- `simulate()`：仅用于软件闭环演示的动态维度数学函数。

典型形状为：

```text
x: [样本数, 输入变量数]
y: [样本数, 目标变量数]
```

### `learning.py`

`build_model()` 根据当前维数构建独立多目标批量高斯过程：

1. 输入按搜索边界归一化。
2. 每个目标分别标准化。
3. 每个目标使用带自动相关维度的 Matérn 5/2 核。
4. `fit()` 通过边缘似然学习模型参数。

`predict()` 返回后验均值和潜在函数标准差。`cross_validate()` 每次留出一个真实样本重新拟合，最终给出 MAE、RMSE 和 R²。

### `optimization.py`

`recommend_target()` 的主要步骤：

1. 在当前边界和约束内建立候选池。
2. 用模型预测每个候选的目标均值和不确定性。
3. 根据 `target`、`range`、阈值或最大/最小化条件计算归一化误差。
4. 用 `weight` 合并多个目标，并按 `risk_aversion` 惩罚不确定性。
5. 从得分最低的候选中选择一批互相不过近的新点。

`recommend_pareto()` 使用 qLogNEHVI。它同时考虑多个目标方向、预测不确定性、已有 Pareto 前沿和候选之间的联合价值。

`recommend_candidates()` 只负责读取 `recommendation.mode` 并转发到对应策略。

### `artifacts.py`

训练模型不能脱离数据和变量定义单独使用。这个模块把以下内容放在同一个训练目录：

- 模型参数及训练时的输入边界。
- 训练数据快照。
- 设置快照。
- 变量名称、类型和顺序签名。

推荐时如果当前变量结构与模型不一致，程序会拒绝加载并要求重新训练。目标值、约束、搜索边界和推荐模式可以修改；变量结构变化则必须重训。

### `__main__.py`

最后阅读命令如何串联以上模块：

- `init`：生成目标列为空的初始实验表。
- `validate`：数据质检和留一验证。
- `train`：训练并保存可重复加载的模型。
- `recommend`：读取已训练模型，执行设置中选择的推荐策略。
- `merge`：把已测量的新批次合并为新的数据版本。
- `demo`：用模拟函数演示相同闭环。

## 3. 边界、约束和风险的含义

关闭显式边界不等于无限搜索。模型只在观测附近有数据支持，因此程序以实际最小值和最大值为基础，再按 `observed_margin` 扩展。扩展越大，外推风险越高。

约束目前是线性的，例如：

```text
1.0 × A + 2.0 × B - 0.5 × C <= 12
```

非线性、条件式或离散类别约束不在当前版本范围内，应先转化为线性规则，或在后续版本增加专门接口。

指定目标反向推荐给出的是“模型认为更可能符合目标的输入”，不是数学上保证能达到目标的逆解。必须通过真实实验验证。

## 4. 建议的调试练习

在 PyCharm 中依次设置断点：

1. `config.py` 的 `return ProjectConfig(...)`：观察 YAML 如何变成配置对象。
2. `data.py` 的 `return unique[:size]`：观察连续变量、整数变量和约束过滤。
3. `learning.py` 的 `return model`：展开核参数和输入/目标变换。
4. `optimization.py` 的 `scores, components = ...`：比较不同目标条件的得分。
5. `__main__.py` 的 `handlers[args.command](args, config)`：观察各命令接收到的参数。

每次修改后运行：

```bash
python -m unittest discover -s tests -v
python -m coating_ai demo --rounds 1
```

自动测试证明软件规则仍然工作，不代表模型已获得足够科研证据。正式使用时仍要检查交叉验证、外推范围、实验误差、平行样和独立验证集。
