# 完整涂层耐久预测与配方推荐：COATING_AI 项目指南

## 1. 研究目标与工作流

本项目研究 MXene/PDA/ZnAl-LDH/BTA-ZIF-8 复合填料对完整防护涂层的影响。核心问题是：**在只知道配方时，可以怎样选择值得做的实验？加入第 1、3、7 天的 EIS 实测后，对第 28 天防护表现的判断能否变得更准？** 目标是较高的后期性能和可重复的达标表现；不把拉开强度、划伤自修复或多年寿命外推作为本项目的主要任务。

一套实验数据库用于训练两个高斯过程（GP）回归模型。两者预测同一个后期指标，但在不同时间点使用不同的信息。

| 模型 | 可用输入 | 输出 | 使用时机 |
| --- | --- | --- | --- |
| D：配方设计 | 复合填料添加量、LDH/MXene 干质量比 | 配方平均第 28 天 logZ 的预测及潜在标准差 | 制备前，评估给定配方或推荐待测配方 |
| F：早期预测 | 同样的两个配方量，加第 1、3、7 天实测 logZ | 同一后期指标的更新预测及潜在标准差 | 第 7 天早期测量齐全后 |

**实验闭环：** 已完成的配方与 EIS → 整理、训练 D/F → 用 D 推荐 → 做实验并测早期 EIS → 用 F 预测 → 测到第 28 天核对 → 将真实标签回填，再训练。F 不参与制备前的候选搜索；尚未测到的 EIS 不能当作可调输入。第 7 天用冻结的 F 预测是推断，不是把新配方加入训练。D 和 F 也不是分别叫作「主动学习」和「贝叶斯优化」的两个模型。

当前项目内的数据适用于流程验证：工作簿有 36 条名义时刻 EIS、2549 个谱点，聚合后 D/F 各六行、四个验证组。原始阻抗保留实测值，但配方输入是流程验证用的假设值，不代表目标体系的实测组成；时间配对和独立重复不能仅凭占位编号确认。当前两个保存模型和第 1 轮候选仅用于检验软件，不作为真实配方优选、模型精度或可靠性证据。

## 2. 配方输入、测量计划与目标

| 项目 | 定义 | 录入或实验要求 |
| --- | --- | --- |
| `hybrid_wt_pct` | 100 × 复合填料干质量 / 全部涂层干固体质量 | 数值 0.2 表示 0.2 wt.%，不含挥发溶剂 |
| `ldh_mxene_ratio` | 干基 LDH 质量 / 干基 MXene 质量（g/g） | 1.5 表示 1.5 g/g。若只能控制投料比，明确标注名义投料比，不与产物实测比例混用 |
| 主目标 `logZ_28d` | 第 28 天面积归一化的 0.01 Hz 阻抗模值取常用对数，再按配方聚合 | 单性能指标，数值越高表示该测试条件下的低频阻抗越高 |
| 最低要求 `minimum_logZ` | 第 28 天终点的性能下限 \(T\) | 在看到最终验证结果前确定。达标不表示在全部浸泡时间都达标 |

研究空间使用两个连续配方量；真实边界由可制备性、原料和实验条件确定。工作簿中的 0.1–1.5 wt.%、0.1–2.0 g/g 和 \(T=10\) 仅为软件验证设置。PDA、BTA-ZIF-8 的引入规则以及树脂、基材、涂覆、固化等工艺应固定或记录。若改变 LDH/MXene 比例会同时改变其他组成，结论应解释为这套配方规则的影响，不归因于单一组分。

正式数据优先覆盖 **1、3、7、14、28 天**，在同一批试片上纵向跟踪：1/3/7 天用于 F，14 天用于中期轨迹，28 天用于训练标签和验证。50 天可作为额外观测；程序允许将后期目标改为 14、28 或 50 天，目标改变后要重建数据和重训，不能混用模型。记录实际暴露时间、介质、温度、面积、膜厚、填料批次、制备日期、仪器设置与质量异常。

### 阻抗换算与重复

原始模值以 Ω 填入 `z_001_ohm`，面积以 cm² 填入 `area_cm2`。程序计算：

$$
y=\log_{10}\left(\frac{|Z(0.01\,\mathrm{Hz})|\cdot A}{1\,\Omega\cdot\mathrm{cm}^2}\right).
$$

如果仪器已经输出 Ω·cm²，先用实际面积换回 Ω，不能把已经归一化的值再乘一次面积。由全谱读取时，用同一个 0.01 Hz 点的实部和虚部计算 \(|Z|=\sqrt{Z'^2+Z''^2}\)，不使用其他频率替代；两种输入都填时必须一致。频谱用于追溯、计算低频点和今后分析；现有 GP 不直接输入所有频点。

每个不同配方用一个 `sample_id`。重新独立称量、配制和制片才用新的 `preparation_id`；同一次配制的多片使用相同配制号、不同 `specimen_id`。测量键为这三个编号加 `day`。同片的多个时间点和同谱的多个频点都不是新增独立配方。

程序在每个配方/时刻先平均同次配制的技术试片 logZ，再对不同配制的结果等权取平均。若各配制均值为 \(y_1,\ldots,y_n\)，标签为 \(\bar y=\sum_i y_i/n\)，配制间样本标准差为 \(s=\sqrt{\sum_i(y_i-\bar y)^2/(n-1)}\)。只有一次配制时 SD 留空。程序按时刻聚合，**不会自动确认各天用的是同一批配制或试片**；正式研究需要按编号核对完整的配对轨迹，记录缺失或排除原因。

## 3. 数据文件与填写方式

主工作簿是 [data/ML_data.xlsx](../data/ML_data.xlsx)；同一套入口即可处理流程验证数据和后续真实数据，无需切换模式。

| 工作表 | 填写要点 |
| --- | --- |
| 配方 | 每配方一行，两个连续输入填齐；`validation_group` 用于把必须留在同一折的同源记录分组，缺省使用配方号 |
| EIS低频 | 每个试片/时刻一行，填实际面积及 0.01 Hz 模值。未测留空，不填 0 |
| EIS全谱 | 原始频率与复阻抗实虚部，保留原始单位和符号；与低频表用相同编号 |
| 新谱模板 | 可填写新谱实虚部；同时在低频表建唯一对应行并填面积 |
| 实验条件 | 填基材、树脂、膜厚、介质、温度等实际信息，未知留空 |
| 参数 | 输入边界、后期时间、最低性能、风险惩罚；概率阈值字段暂不参与计算 |
| 来源映射 | 原材料、原谱文件、哈希、时间和质量说明；随真实数据一起维护 |

- `data/raw_eis/` 保留本地原始谱；`data/provenance/eis_source_audit.json` 保留源文件级的可追溯记录。这些资料不需要每次训练重新导入。
- `data/round_01/` 包含三个待测候选、54 行低频记录空位（每候选三次配制占位 × 六个时间点）和一份全谱空白格式。`candidates_to_measure.csv` 的输入和编号用于连接实验，实测值填 `measurements.csv`，必要时另填 `spectra.csv`。不把预测 CSV 当成仪器记录。
- `prepare-eis` 重建派生表，不改工作簿、轮次 CSV 或原谱。`design_training.csv` 收录有后期标签的配方；`early_training.csv` 还要求 1/3/7 天齐全。`design_prediction_inputs.csv` 收录已填写配方但缺后期的记录；`early_prediction_inputs.csv` 再筛出早期数据齐全的记录。`repeat_statistics.csv` 保存配方均值、SD 和配制数。
- 同一次整理可读取工作簿和 **一个** `--new-data` 轮次。多轮长期使用时，将已完成轮次归并进主工作簿并保留原 CSV；同一批不能在工作簿和参数中重复导入。
- `data/project.yaml` 和 `data/early_model.yaml` 是 D/F 有效配置。工作簿参数是常规修改入口；每次整理会重建 YAML。自定义约束、目标模式、候选池或批次大小应在整理后另存 YAML，并用 `--settings` 明确指定，不把手改派生文件当作永久配置。

## 4. 模型、验证与推荐的数学含义

### 高斯过程回归

两个模型各自拟合 \(y=f(x)+\epsilon\)。代码先归一化输入、标准化目标，在 GP 上使用 Matérn 5/2 核和各维独立长度尺度（ARD），用边缘似然拟合。归一化后的两点 \(u,u'\) 有距离 \(r=\sqrt{\sum_j[(u_j-u'_j)/\ell_j]^2}\)，核为：

$$
k(u,u')=\sigma_f^2\left(1+\sqrt5\,r+\frac{5r^2}{3}\right)e^{-\sqrt5\,r}.
$$

长度尺度 \(\ell_j\) 用于模型的距离计算，不能直接解释为物理因果。推断时转换回原始 logZ 标度，输出 `*_predicted`（潜在响应均值）与 `*_latent_std`（潜在响应后验标准差）。后者**不是**独立制备之间的 SD、未来单次测量的完整预测区间，或达标概率。

### 留组验证

`validation_group` 的所有配方一起留出，训练、缩放与标准化在训练折内完成；显式物理边界由实验方案给定。没有额外分组时可按独立配方留一。若研究跨批次泛化，须用能隔离批次的数据设计和拆分，而不是将同批试片随机打散。当前软件训练入口要求至少六条完整记录，且每个留出折需至少两条训练记录；**可运行门槛不是科学样本量**。

折外结果可用 \(\mathrm{MAE}=\mathrm{mean}(|\hat y-y|)\)、\(\mathrm{RMSE}=\sqrt{\mathrm{mean}((\hat y-y)^2)}\) 和 \(R^2\) 衡量。训练日志中的指标是当前数据的验证输出，不是新材料体系的性能保证。当前命令输出汇总指标；正式比较还应保存逐配方折外预测、分组、秩相关和阈值判定。

### 制备前怎样推荐

当前 D 在可行域内用 Sobol 序列产生有限候选池，预测每点的均值 \(\mu\) 与潜在标准差 \(\sigma\)，去除训练中已经出现的点，并优先选彼此分散的候选。当前单目标 `at_least` 对候选计算：

$$
S=\frac{\max(T-\mu,0)+\lambda\sigma}{s_\mathrm{score}}.
$$

分数越低越靠前；\(\lambda\) 是 `risk_aversion`，\(s_\mathrm{score}\) 是目标评分尺度 `tolerance`。这不是概率约束：均值超过阈值后缺额为零，不惩罚超标，但也不会仅因均值更高而额外加分。正式实验若要「可靠达标后优先更高性能」，应先明确排名规则再做前瞻验证，不能把当前评分写成已实现的可靠优化。

显式上下界可在配置中关闭，此时**搜索范围**从训练观察范围及 `observed_margin` 得到；初始设计尚无训练数据，须先给显式可行边界。可选线性约束应基于真实工艺。通用代码保留多目标 Pareto/qLogNEHVI 分支，只有当存在多个可独立定义的实测目标时才使用；当前单目标阈值候选排序不是该分支，也不等于基于预期改进的单目标 BO。

## 5. PyCharm 中怎么跑

在 PyCharm 中打开项目根目录，选择 Conda 的 `AI` 解释器。若当前环境尚未安装项目，在根目录执行一次：

~~~bash
conda activate AI
python -m pip install -e .
python -m coating_ai --help
~~~

### 第一步：整理与训练

已有可加载模型在 `output/design`、`output/early`；要检查现有接口可以直接加载，不需要重训。如果录入了新的完整数据，先整理后再训练：

~~~bash
python -m coating_ai prepare-eis
python -m coating_ai train --settings data/project.yaml --data data/design_training.csv --name design_round02
python -m coating_ai train --settings data/early_model.yaml --data data/early_training.csv --name early_round02
~~~

有单独的轮次表时，把第一条替换为 `python -m coating_ai prepare-eis --new-data data/round_01`，目录改成实际待导入轮次。正常训练包含留组验证。初始无数据时，可先用 `python -m coating_ai init --n 12` 在可行域生成 `output/initial_design.csv`，再把配方编号及两个输入录入工作簿；该表没有实验标签。可打印 Excel 初始表可用 `python -m coating_ai.generate_doe_excel --n 12`。

### 第二步：推荐并冻结候选

以已保存的 D 为例；正式推荐必须换成经真实体系数据训练的 D：

~~~bash
python -m coating_ai recommend --settings output/design/settings_snapshot.yaml --run output/design --name round_02 --out-data data/round_02
~~~

`output/round_02/` 记录候选、预测、使用的设置和来源模型；`data/round_02/` 是实际回填的空白测量模板。每轮用新名称，已经存在的结果目录和实验轮次不会被覆盖。先确认边界和可制备性，再安排制备。若只是接着填写现成 `data/round_01/`，无需重新推荐。

### 第三步：第 7 天更新预测

填好同一批试片的 1/3/7 天真实测量，未测的后期仍留空。以下以第 1 轮和现成 F 为例：

~~~bash
python -m coating_ai prepare-eis --new-data data/round_01
python -m coating_ai predict --settings output/early/settings_snapshot.yaml --run output/early --data data/early_prediction_inputs.csv --name round_01_day07
~~~

早期三天不全时不会生成 F 待预测行。需要做制备前预测时，用 D 及 `data/design_prediction_inputs.csv`。`predict` 只保存预测表；正式实验应在揭晓后期结果前另行保存当时的输入表、设置、训练目录引用和测量截止时间。训练/推荐已保存的 `settings_snapshot.yaml` 是可复现运行的重要部分，不应拿不匹配的设置加载模型。

### 第四步：验证后期真值，再开始下一轮

在同一批试片上继续测 14/28 天。先在不更改模型或阈值的前提下，对照 **D 制备前预测、F 第 7 天预测、28 天实测**，记录各独立配制的值、预测误差和是否达标。评价完成后，回填真实后期数据，重跑整理和 D/F 训练；新配方只有在相应标签及特征齐备时才进入训练。用下一轮名称保存新模型，不用预测值补训练标签。

## 6. 正式研究如何验证

建议先确认可制备范围及测试协议，再用二维空间填充设计安排约 12 个初始配方，覆盖空间的边缘和中间；每配方约 3 次独立配制、每次至少一片跟踪五个时点，作为可调整的起点。先看预实验的配制波动、可分辨效应和仪器负荷，再定最终样本数。纯树脂可作空间外对照，LDH/MXene 比值不适用，不强行编成普通配方点。

| 要回答的问题 | 最小比较与证据 |
| --- | --- |
| 早期时间信息是否有效？ | 相同训练配方、留出分组和模型族下，对比训练均值基线、仅配方、配方＋第 7 天、配方＋第 1/3/7 天。用折外 MAE/RMSE、排序及阈值判定衡量增益。另用 Ridge 等简单方法作模型对照 |
| 推荐是否优于简单选点？ | 在同一配方范围、相同已知数据下，冻结 D 推荐与预先规定的对照（如 Sobol 或传统响应面）。测完所有计划候选，不能只验证预测好的点 |
| 高性能能否重复？ | 对关键配方独立重配并保存每次的真实值、均值、SD 和达标次数。需要区分配方平均达标与未来一次配制达标 |
| 能否报告达标概率？ | 只有建立包含过程波动的单次制备预测分布并以独立数据校准后才能报告。现有软件尚未实现，不能用 `latent_std`、风险惩罚或少量全达标重复替代 |

可在有数据后做变化量、时间点与谱形消融，不把更多特征默认当作更好。比较 D 和 F 可以检验「早期信息改善预测」；若要声称「早期信息改变采集策略并改善下一轮配方」，还要明确定义新决策规则，做同信息、同约束下的前瞻对照。当前 D 仍等后期真实标签回填，F 不自动更新下一轮采集策略。

论文宜依次呈现：**问题与假设 → 材料和采样协议 → D/F 信息分工、分组与冻结规则 → 预测增益与实验证据 → 使用边界**。建议主图覆盖：① 两时点工作流；② 配方空间、EIS 轨迹和独立重复；③ 不同信息量的折外预测与误差；④ 早期时间点消融；⑤ 关键配方的重复与真实阈值；⑥ 新配方的制备前预测、第 7 天更新与第 28 天实测。消融、排序、概率校准与论文作图是正式分析任务，不是现有 CLI 自动产物。研究贡献取决于能否证实信息增益和推荐价值，不以实验预算或材料结构创新代替这个问题。
